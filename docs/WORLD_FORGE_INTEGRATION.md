# WORLD FORGE: интеграция LUDOSCOPE 0.4.0

LUDOSCOPE остаётся самостоятельным локальным инструментом. WORLD FORGE, Chronicler, Universal Modder и Compound Engineering не встраиваются и не выдаются за доступные сервисы. Интеграционный слой предоставляет структуру передачи работы агентам без ручного копирования текста.

## Границы модулей

| Слой | Реальный компонент | Назначение |
|---|---|---|
| Design Knowledge Engine | DesignKnowledgeEngine + KnowledgeRegistry + Lens Engine | Отбор знаний, линзы, источники и ограничения |
| Analysis Engine | AnalysisEngine + существующие mechanics/systems/labs | Формальные/структурные проверки концепции, механики, цикла, прогрессии, GDD |
| Recommendation Engine | RecommendationEngine | Редактируемые варианты спецификации, проверяемые гипотезы и планы |
| Evaluation Engine | EvaluationEngine + seeded simulator + mechanic checks | Описательная интерпретация данных, инварианты, сравнения |
| Integration Layer | LudoscopeAgentApi, MCP registration, FIP schemas, ChroniclerAdapter | Корреляция запросов, типы, разрешения, история и передача результата |

Это модули общего процесса TypeScript, а не пять микросервисов. Они переиспользуют действующее ядро. Вызов не требует LLM, API-ключа или отдельной подписки. Аналитическая полнота ограничена формализованными входами: API не притворяется автономным творческим директором и не заменяет Codex.

## Сквозной цикл

1. Оркестратор назначает стабильные project_id/task_id; каждому вызову — новый request_id. Передаёт author_goals, creative_principles, constraints, аудиторию, ссылки на спецификации/ревизии и механику.
2. `analyze_mechanic` возвращает findings, источники, альтернативы с candidate mechanic, гипотезы и критерии проверки. История Chronicler учитывается, если подключена.
3. Автор или уполномоченный агент выбирает направление. Оркестратор передаёт инженерному агенту выбранную спецификацию вместе с constraints, creative_principles, hypothesis IDs, validation и artifact_refs. LUDOSCOPE не объявляет эту передачу согласием изменить канон.
4. Инженер возвращает ревизию реализации, ссылки на тесты, условия и наблюдения. Эти артефакты добавляются в artifact_refs; результаты — в evaluate_playtest с `data_origin:engineering_test`. Симуляции имеют data_origin:simulation; реальные наблюдения людей — human_playtest.
5. `evaluate_playtest` связывает metric + hypothesis, описательно сравнивает порог и сохраняет исходную гипотезу. Значимость и причинность не объявляются.
6. `analyze_mechanic` получает реализованную спецификацию и prior_analysis с оценкой результатов. Рекомендации пересматриваются, исходный анализ не изменяется. project_id/task_id обязаны совпасть.
7. После разрешения `publish_analysis(commit:true)` передаёт результат настроенному ChroniclerAdapter. Без разрешения — только preview; без Chronicler — полезный локальный результат с неполной историей.

Исполняемый пример: `node examples/world-forge/workflow.mjs`. Он использует in-memory историю и явно синтетические инженерные данные для проверки контракта; реальные игроки, инженерный агент и удалённый Chronicler в нём не запускаются. Другой пример `mcp-client.mjs` запускает настоящий stdio MCP-сервер из сборки и выполняет вызовы SDK.

## Сохранение контекста

task_id — локальное расширение предварительного FIP-профиля; его согласование с официальным контрактом ещё предстоит. Отсутствующий task_id разрешён для discovery, но для рабочего цикла задавайте его явно. session_id/agent_id сохраняются и не используются как полномочия. По URI артефактов ничего автоматически не загружается и не выполняется. Утверждения источника, дизайнерская интерпретация, проектные факты и моделирование различаются claim_type.

Полный WORLD FORGE, реальные официальные адаптеры остальных плагинов, сетевой HTTP API, асинхронная очередь и свободная генерация творческих решений не реализуются в этом обновлении. Дальнейшее согласование FIP выполняется адаптером и contract tests.
