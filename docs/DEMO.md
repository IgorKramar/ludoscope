# Демо: голод, производство и проверяемое ограничение

После `npm ci --ignore-scripts` и `npm run check` выполните:

```sh
npm run demo
```

Команда создаёт отдельные временные каталоги для игрового проекта и отчёта. Игровой каталог удаляется после проверки, результаты остаются по пути из консоли. Исходные примеры не меняются. Для сохранения в выбранное место:

```sh
npm run demo -- --output /tmp/ludoscope-demo
```

Папка должна быть новой. Отказ при повторном использовании защищает предыдущий результат.

## Исследовательский вопрос

Автор хочет, чтобы голод поддерживал планирование экспедиций. Для вычислительного примера задан более узкий вопрос: **нарушает ли производство пищи ограничение food ≤ 12 за десять тактов?**

[Модель](../examples/survival/economy.json) начинает с food=5, energy=5. На каждом такте ферма тратит 1 energy и производит 2 food; затем питание тратит 1 food и восстанавливает 1 energy. Процессы идут в объявленном порядке. Seed=42 сохраняется, хотя в этой модели нет случайных процессов.

| Условие | Исходная модель | Экспериментальный кандидат |
| :--- | ---: | ---: |
| Выход фермы | 2 food | 1 food |
| Число тактов | 10 | 10 |
| Итоговый запас food | 15 | 5 |
| Итоговый запас energy | 5 | 5 |
| Нарушений food ≤ 12 | 3 | 0 |

Эти значения проверяются утверждениями в [runner](../scripts/demo.mjs). Отчёт формируется из результатов конкретного запуска. Исходная модель нарушает ограничение на тактах 8, 9 и 10.

Кандидат проходит именно это ограничение на заданном горизонте. Уменьшение производства может ухудшить темп игры; выбор варианта требует решения автора и дальнейших проверок.

## Почему проверяется число нарушений

Среднее количество пищи по всей траектории может скрыть превышение верхней границы. Поэтому до запуска формируется гипотеза о `invariant_violations <= 0`, а в агентный API передаётся реальное число нарушений — 3.

Результат имеет происхождение `simulation`, статус утверждения `MODEL_RESULT` и ноль человеческих участников. Проверяемая гипотеза получает описательный результат `descriptively_contradicted`; её тип остаётся `DESIGN_HYPOTHESIS`.

## Что делает полный цикл

1. Создаёт проект, сохраняет версию механики и открывает её через новый экземпляр хранилища.
2. Сканирует входные документы; анализирует механику и зависимости.
3. Формулирует эксперимент до вычисления результата.
4. Выполняет исходную симуляцию дважды и проверяет детерминированность.
5. Сравнивает один изменённый параметр на том же горизонте.
6. Передаёт модельные измерения в API и пересматривает рекомендации.
7. Проверяет сохранение project/task IDs и формирует preview публикации.
8. Сохраняет отчёты и контрольные суммы.

Chronicler не подключён. История помечается неполной, удалённая публикация не выполняется.

## Сохранённые файлы

| Файл | Содержимое |
| :--- | :--- |
| `report.md` | Краткий разбор, таблица расчётов, граф и вопросы для плейтеста |
| `analysis.md` | Развёрнутый анализ с гипотезами, компромиссами и происхождением |
| `data.json` | Входы, исходные хеши, траектории, API-результаты и контекст |
| `manifest.json` | Итог проверок и SHA-256 остальных файлов |

Manifest записывается последним. Для проверки завершённого прогона он должен корректно разбираться как JSON, а контрольные суммы перечисленных файлов — совпадать; одно наличие файла после прерванной записи недостаточно. Метаданные запуска и UUID меняются; детерминированность относится к результату модели при тех же входах и seed.

CI запускает этот сценарий на Node.js 22 и 24. Отчёты можно скачать в **Artifacts** соответствующего [GitHub Actions run](https://github.com/IgorKramar/ludoscope/actions/workflows/quality.yml).

Это тестовый проект. Пилот на реальном игровом репозитории, независимая оценка Skills и исследование с игроками остаются отдельными задачами.
