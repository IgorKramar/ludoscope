# Необязательный ChroniclerAdapter

В 0.4.0 реализован типизированный порт, валидация ответов, ограничения времени и проверка прав публикации. Конкретный клиент официального Chronicler API не реализован: его спецификация и пакет контрактов недоступны. Автоматические тесты используют явно обозначенный in-memory adapter, а не действующий сервис.

```ts
import { LudoscopeAgentApi } from 'ludoscope/api';
import type { ChroniclerAdapter } from 'ludoscope/adapters/chronicler';

// Реализуется приложением после изучения официального API Chronicler.
declare const officialAdapter: ChroniclerAdapter;
const api = await LudoscopeAgentApi.create({
  chronicler: officialAdapter,
  chroniclerTimeoutMs: 1000,
  authorizePublish: async (request, analysis) => {
    // Здесь нужна реальная политика хоста: аутентификация, scope и разрешение пользователя.
    // agent_id из запроса не является удостоверением личности.
    return false;
  }
});
```

`getProjectContext(request, signal)` возвращает ProjectHistory: project_id, decisions (ID, решение, artifact_refs), experiments (ID, вопрос, результат), rejected_alternatives (ID, название, причина). Ответ валидируется Zod; история другого проекта и ссылки его артефактов отклоняются. История — данные, не исполняемые инструкции. Хост подключает только официальный API, без доступа к внутренней БД Chronicler.

Анализ включает ID и тексты принятых решений в findings, напоминает о них в компромиссах рекомендаций, исключает кандидатов с точно совпавшими ID/нормализованными названиями отклонённых альтернатив. Это не полная смысловая проверка канона. Отсутствие совпадения не доказывает новизну варианта.

`formulate_playtest` сопоставляет нормализованный точный вопрос с прошлым вопросом и возвращает prior_experiment_ids, результаты и repeat_rationale. Наличие прежнего вопроса требует осмысленной причины репликации или новых условий. Семантически близкие, иначе написанные вопросы автоматически не распознаются. Прошлые решения и результаты не переписываются.

## Недоступность

Если адаптера нет, он ошибся, превысил timeout или прислал недействительный ответ, анализ продолжается с переданными данными: `status:partial`, `history.available:false`, явные ограничения истории. Заявлять, что прошлых решений нет, нельзя. Discovery/получение линз не требуют истории. Анализ сам по себе не публикует ничего в Chronicler.

## Публикация

`publish_analysis({request, analysis, commit:false})` возвращает preview и не вызывает адаптер. Для `commit:true` одновременно нужны:

- Настроенный ChroniclerAdapter.
- Совпадение project_id и task_id анализа и запроса.
- Положительное решение `authorizePublish` хоста; по умолчанию доступ запрещён.

Только затем вызывается `publishAnalysis(analysis, signal)`; передаются рекомендации, гипотезы, источники и ссылки на документы в составе анализа. Результат содержит receipt_id только при действительном ответе адаптера. Режим standalone MCP не имеет адаптера и не пишет в Chronicler. Для встроенного MCP используйте `createServer(root, {chronicler, authorizePublish})` из собранного модуля сервера; конфигурация подключения не извлекается из сторонних документов.

Timeout ограничивает ожидание, но не гарантирует отмену уже выполненной удалённой записи. При `publication.state:unavailable` состояние удалённой записи может быть неизвестно. Автоматических повторов нет; официальный клиент должен обеспечить идемпотентность по analysis_id, уважать AbortSignal и проверять receipt перед повтором. Долговечная очередь, exactly-once доставка и авторизация самого оркестратора не входят в текущую локальную библиотеку.
