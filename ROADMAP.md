# Путь от 0.6 к 1.0

## Завершённый этап 0.5.0

- Проверка целостности evidence/artifact/hypothesis ссылок и сохранение происхождения между итерациями.
- Совместная оценка нескольких критериев гипотезы и устойчивое среднее для конечных больших измерений.
- CI на Node.js 22/24 с MCP, установленным пакетом, схемами и документацией.
- Воспроизводимое демо с фактическими расчётами, JSON/Markdown и контрольными суммами.
- Портфолио-кейс, оформление GitHub и руководства на русском/английском.

## Завершённый этап 0.6.0

- Строгая трассировка объявленных цепочек и файловых fingerprints через библиотеку, CLI и MCP.
- Пилот Hydrocraft Reinvented: закреплённые исходники, чтение рецептов и callback, оригинальная модель, четыре сценария стартового запаса и проверка ресурсного учёта.
- Отдельные статусы пропущенных тестов и плейтестов; мод не изменяется.

## Следующий этап: проверка пилота в игре

На отдельном тестовом профиле Project Zomboid проверить инвентарь, callback и представление оборота веретён. Затем с реальными участниками исследовать понимание стартового запаса. До получения этих данных не утверждать дефект дизайна и не менять авторское решение. Игровая сборка и участники потребуют отдельного доступа и организации исследования.

## Требования к 1.0

1. Полная ru/en локализация вычислительных выводов; независимые оценки Skills с фиксацией разногласий.
2. Расширение проверенного содержания остальных школ и первичных исследований SDT, Flow, learning, accessibility.
3. Транзакционная инициализация, безопасные миграции, адресные diff документов.
4. Инкрементальный индекс, семантическая проверка объявленных design–code links и адаптеры подтверждённых API движков.
5. Дополнительные формальные модели и bounded worker jobs с отменой для тяжёлых вычислений.
6. Проверки установки/обновления на разных платформах и клиентах Codex.
7. Согласование FIP с официальным контрактом, реальный Chronicler API с авторизацией/idempotency и межплагинный цикл.

Визуальный редактор графа, интерактивный баланс, GitHub Issues и Universal Modder — после стабильного ядра и изучения реальных API. Полный WORLD FORGE не входит в эту доработку.

Критерии готовности определяются исходным ТЗ; интерес и оригинальность игры требуют авторской работы и исследований.
