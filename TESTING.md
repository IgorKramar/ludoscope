# Тестирование

```bash
npm ci --ignore-scripts
npm run check
npm run demo
```

Сборка обязательна перед интеграционными тестами: они запускают реальный CLI и MCP stdio из `dist`, а не только импортируют функции исходного кода. Нужен Node.js 22 или новее. Тесты не требуют сети, API-ключа, установленного Codex или внешнего игрового движка.

`tests/core.test.ts` проверяет строгие схемы и лимиты вычислений, ссылочную целостность и циклы зависимостей, транзитивное влияние изменений, конечные автоматы, воспроизводимость stochastic-модели по seed, начальные и последующие нарушения инвариантов, поиск прибыльной конверсии, learning prerequisites, формальный канон, распределение процедурного контента и разделение наблюдений, измерений и субъективных отзывов. Повторные строки одного участника не увеличивают количество участников.

`tests/integration.test.ts` проверяет создание и повторное открытие проекта, preview и создание решений, отказ перезаписи, изменение fingerprints, ограничения файлового размера, traversal, символьные ссылки на файлы и каталоги. Пары настоящих MCP SDK Client/Server через InMemoryTransport проверяют список инструментов, annotations, схемы успешных ответов и ошибочные вызовы. Отдельно запускается MCP через StdioClientTransport. CLI отдельно проверяет preview/commit разрешённого импорта знаний, нормализацию имени пакета и поиск после повторного открытия. CLI-сценарий проходит init → analyse → report → preview → commit → context → validate → doctor.

Каждый тест использует собственный временный каталог и удаляет его после завершения. Интеграционные проверки требуют поддержки symlinks и hard links локальной файловой системой. Проверки закрывают обычные пути обхода, но не являются доказательством защиты от конкурентных файловых TOCTOU-атак.

Четыре демонстрации и ожидаемые формальные результаты описаны в [examples/README.md](examples/README.md). Есть отдельная регрессия минималистичной головоломки: инструмент не добавляет экономику, производственные цепочки и RPG-прокачку. Эта проверка относится к детерминированному ядру; она не доказывает отсутствие жанровой предвзятости модели Codex.

AI Skills требуют ручной оценки: релевантность источников, разделение гипотез и доказательств, различие альтернатив, уважение канона и осмысленность инструментальных вызовов. Автоматические тесты не доказывают творческое качество, удобство интерфейса или удовольствие игрока. Реальные пользовательские исследования и установка в живой Codex в этот suite не входят.

Набор ручных запросов и критериев: `tests/fixtures/ai-evaluation.json`. Он включает пять жанровых/аналитических сценариев и источник с prompt injection. Сохраните оценщика, версию модели, транскрипт инструментов и разногласия; готовых качественных оценок файл не содержит.

Проектная память: тесты проверяют preview без записи, неизменяемые v1/v2 артефакты, повторное открытие последней механики, соответствие ID/версии документа. Обновление графа требует hash из preview; тесты проверяют отказ без hash, конфликт устаревшего preview, сохранение прежних байтов в history и блокировку symlinks в графе, артефактах и истории. Все инструменты, включая две операции записи, проходят положительные и отрицательные MCP-вызовы; в общем контрактном прогоне запись остаётся выключенной.

Фактический снимок проверки релиза, включая установку в изолированную конфигурацию Codex CLI: [docs/verification.md](docs/verification.md). `node scripts/smoke-installed.mjs /absolute/installed/plugin` проверяет уже установленную копию через stdio; сам тестовый suite не устанавливает плагины в пользовательскую конфигурацию.

## Надёжность и CI 0.5.0

Workflow [Quality](.github/workflows/quality.yml) запускает `npm run check` на Node.js 22 и 24. Затем проверяет отсутствие diff после генерации схем, агентный workflow, stdio MCP, воспроизводимое демо и установленный npm-пакет. Отчёты demo сохраняются в artifacts соответствующего запуска на 14 дней.

`tests/agent-integrity.test.ts` покрывает сохранение артефактов, конфликтующие/поддельные IDs, определения гипотез при новых целях, отсутствие ссылок, протокол эксперимента и лимиты.
`tests/evaluation-integrity.test.ts` проверяет совместные критерии, пропуски, независимые гипотезы, переполнение и число метрик.
`tests/history-integrity.test.ts` проверяет деградацию при конфликтующей истории, обновление источников и происхождение перенесённых результатов.
`tests/report-integrity.test.ts` проверяет отображение критериев, происхождения и безопасное представление импортированной разметки.

`scripts/check-docs.mjs` проверяет относительные Markdown-ссылки на существующие файлы. Содержимое внешних URL и якоря не проверяются. Скрипт не заменяет редакторское чтение или визуальную проверку.

[Демо](docs/DEMO.md) запускается в изолированном временном проекте. Модельные вычисления реальны, человеческие наблюдения не создаются. Сценарий WORLD FORGE с in-memory Chronicler отдельно использует явно обозначенные синтетические инженерные данные.

Фактический снимок 0.5.0: [95 тестов и полный CI](docs/verification-0.5.0.md), включая установку пакета и два варианта модели. Результаты относятся к указанной ревизии; новые коммиты имеют отдельные CI-прогоны.

## Трассировка и игровой пилот 0.6.0

`tests/traceability.test.ts` проверяет ссылки и стадии, исходные байты, диапазоны строк, изменённые/отсутствующие файлы, обход путей, symlinks, лимиты, повторное использование снимка файла, закреплённый HEAD, dirty state и отмену. `tests/hydrocraft-pilot.test.ts` проверяет порог запаса, учёт ресурсов на каждом шаге, отсутствие станции, пропущенный callback, provenance, CLI с отдельным корнем, контрольные суммы отчёта, отказ перезаписи и отсутствие записей в исходный проект.

`npm run pilot:hydrocraft` работает офлайн и не подтверждает соответствие внешним исходникам. Для проверки выбранных файлов используйте `npm run pilot:hydrocraft -- --source /path/to/clean/pinned/checkout`. Этот запуск читает исходники, но не исполняет мод. CI запускает офлайн-режим исходной и установленной копии; внешнее GitHub-хранилище не является зависимостью тестов.

Фактический отчёт 0.6.0: [проверки и ограничения](docs/verification-0.6.0.md), [результаты Hydrocraft](docs/hydrocraft-0.6.0.json).
